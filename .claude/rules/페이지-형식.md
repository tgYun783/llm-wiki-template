# wiki 페이지 형식 (wiki/ 파일을 다룰 때 읽힌다)

불변 규칙(절대 규칙, 페이지 유형, 정확성 규칙, 도메인 목록)은 볼트 `CLAUDE.md`에 있다. 여기는 페이지를 쓸 때의 세부 형식이다.

## 페이지 템플릿

위치(frontmatter는 파일 맨 첫 줄, 그 바로 다음 핵심 한 줄 callout)는 `CLAUDE.md` §3.2. 전체 모양:

```markdown
---
type: concept
tags: [도메인/지식관리, 생산성, 집중]
created: 2026-09-24
updated: 2026-09-24
sources: ["[[요약-딥워크]]"]
---

> [!abstract] 핵심 한 줄
> 이 내용에서 내가 가져갈 것 한 문장. (행동/판단에 쓸 수 있는 형태로)

# 제목

## 요약
...

## 상세
...

## 연결
- [[관련-페이지]] — 어떻게 연결되는지 한 줄

## 출처
- [[요약-딥워크]] ← raw: `2026-09-24_딥워크-3장-메모.md`
```

`source` 페이지는 frontmatter에 원본 정보를 추가한다:

```yaml
type: source
raw: "2026-09-24_딥워크-3장-메모.md"     # raw/ 안의 파일명
source_url: "https://..."              # 웹 자료일 때
author: "[[칼-뉴포트]]"                 # 저자·발표 주체 (entity 페이지 링크)
```

## 작성 세부
- **[[위키링크]]를 적극적으로.** 본문에서 다른 페이지의 개념·인물·도구·프로젝트가 처음 등장하면 링크한다. 아직 없는 페이지라도 중요하면 링크를 걸어 두고(빨간 링크) 건강검진 때 페이지 생성 후보로 삼는다. 단, 상위 페이지가 있는 entity(작품 속 요소, 조직의 하위 제품 등)는 빨간 링크 대신 아래 생성 기준에 따라 섹션 링크를 쓴다.
- 링크는 파일명 기준: `[[딥워크]]`, 표시명이 필요하면 `[[딥워크|딥 워크]]`.
- **인상 깊은 문장**은 원문 그대로 인용하고 출처(책·쪽수·타임스탬프)를 붙인다:
  ```markdown
  > "인용문" — 저자, 『책』 p.123
  ```
- 상충 callout 형식:
  ```markdown
  > [!warning] 상충
  > [[요약-A]]는 X라고 하지만 [[요약-B]]는 Y라고 한다. (날짜·맥락 차이 등 메모)
  ```
- **상충 포인터**: 상충 callout은 한 곳(보통 개념·허브 페이지)에만 두고(canonical), 그 상충에 걸린 진술을 직접 담은 다른 위키 페이지(각 `요약-` 페이지 등)에는 그 진술 곁에 canonical callout으로 가는 줄을 둔다. 예: `- 상충: 이 값 → [[개념-페이지#절 제목]]`. 진술을 담지 않고 링크만 하는 페이지에는 두지 않는다.
- **할 일** 형식: `- [ ] 내용 (담당, 기한) — 출처 [[요약-회의]]` (해당 `project` 페이지에 모은다).
- 기준 표시 `(기준: 2026-09)`는 줄 끝, 섹션 제목(그 섹션 전체에 적용), 또는 `source` 페이지의 `## 기본 정보` 제목(그 페이지 전체에 적용, 예: `## 기본 정보 (기준: 2025-07)`)에 붙일 수 있다. 원문 각주에 단서(측정 조건, 제한, 버전 차이)가 있으면 함께 적는다.
- **entity 페이지 생성 기준**: 자료 2건 이상에서 언급되거나, 다른 페이지 2곳 이상에서 반복 등장할 때만 독립 페이지로 만든다. 그 전에는 상위 페이지(작품·조직 등)의 섹션으로 두고 `[[엘든링#말레니아]]`처럼 섹션 링크를 건다. 독립 페이지로 옮길 때는 원래 섹션에 한 줄 요약 + 새 페이지 링크를 남긴다 (기존 링크 보존). 이 기준은 소급 적용하지 않는다. 검사기가 `sources` 수와 들어오는 링크 수로 확인한다 (검사 도입 전부터 있던 entity는 경고만).
- **결정 사항**은 `project` 페이지의 `## 결정 로그`에 `- YYYY-MM-DD: 결정 내용 — 이유 — [[출처]]` 형식으로 누적한다.

## project 페이지와 프로젝트 폴더의 역할 분담
**기준: 코드가 바뀔 때 같이 바뀌어야 하는 것은 프로젝트 폴더, 프로젝트가 끝나도 가치가 남는 것은 위키.** 같은 내용을 두 곳에 복사하지 않는다 (복사본은 반드시 낡는다).

| 프로젝트 폴더 (`docs/plan.md`, 프로젝트 CLAUDE.md 등) | 위키 `project` 페이지 |
|---|---|
| 구현 단계, 작업 목록, 일정 | 목표, 현재 상태, 폴더 경로 |
| API 설계, 폴더 구조, 설정값 | **결정과 그 이유** (결정 로그) |
| 작업 중 메모, 디버깅 기록 | **배운 점, 실패에서 얻은 교훈** |
| | 다른 프로젝트·개념과의 연결 |

- 코드가 있는 프로젝트의 `project` 페이지 frontmatter에는 `repo: "/절대/경로"`와 `status: 진행중|보류|완료`를 넣는다. 세부 계획은 본문에 옮기지 말고 경로만 적는다.
- `project` 페이지의 할 일은 **위키 차원의 할 일**(자료 찾기, 회고 넣기 등)만 둔다. 구현 작업 목록은 프로젝트 폴더에 둔다.
- 흐름:
  1. **시작** — `project` 페이지 생성 (목표, repo 경로, 관련 개념 링크)
  2. **진행 중** — 계획·작업은 프로젝트 폴더에서만 관리. 중요한 결정은 그 세션에서 "위키에 넣을까요?" 제안을 받아 둔다.
  3. **중요한 단계 완료 / 종료** — 회고 메모를 `raw/YYYY-MM-DD_<프로젝트>-회고.md`로 넣고 자료 넣기 → 결정 로그·배운 점·개념 페이지 갱신, `status` 갱신

## index.md 형식
- 카테고리 순서: 📥 자료 요약 · 💡 개념·멘탈모델 · 🧑‍💼 인물 · 🛠️ 도구·서비스 · 🏢 조직 · 📚 책·작품·게임 · 🧩 작품 속 요소 · 🧭 주제 종합 · 📁 프로젝트·업무 · ✨ 아이디어 · 🔍 분석·Q&A
- 자료 요약은 세부 분류(기사/트렌드 · 공식 문서/레퍼런스 · 강의/영상/팟캐스트 · 책 · 업무/회의 · 개인 메모)로 나눈다.
- 항목 형식: `- [[페이지명]] — 한 줄 설명 (YYYY-MM-DD)`
- 🧩 작품 속 요소는 작품별 소제목(`### 엘든링`) 아래에 둔다.
- 각 카테고리 안에서는 최신 항목이 위로.
- 새 카테고리가 필요하면 추가하고 이 파일의 목록도 갱신한다.
