# 건강검진 (Lint)

핵심: 기계 점검은 검사기, 판단이 필요한 항목은 직접 본다. 결과는 **표로 보고**하고, 고치는 것은 **사용자 확인 후**. 고쳤으면 반드시 `wiki-verify`.

## 절차
1. `python3 .claude/wiki_lint.py`로 기계 점검.
2. 아래 점검 항목 중 사람의 판단이 필요한 것(5·8번 등)을 검토한다. 맨 아래 조건부 규칙의 조건도 확인한다.
3. 결과를 표로 보고한다. 예: `| 번호 | 점검 항목 | 결과 | 건수 | 조치 제안 |` (자동 수정 가능 / 사용자 판단 필요를 구분).
4. 자동 수정 가능한 것(링크 추가, index 정리, 형식 보정)은 사용자 확인 후 일괄 수정한다. raw 파일명 위반과 사용자가 직접 고친 내용은 고치지 않고 보고만 한다 (절대 규칙 1·3).
5. 검증 루프 — `wiki-verify` 스킬. 그 3단계에서 log.md에 `lint` 항목과 `- 검증:` 줄을 남긴다.

## 점검 항목
1. **필수 형식** — frontmatter 누락, 핵심 한 줄 callout 누락, 도메인 태그 누락, 파일명 규칙 위반, 하위 폴더 존재 여부
2. **고아 페이지** — index.md·log.md 외에는 들어오는 링크가 없는 페이지
3. **빨간 링크** — 링크는 있는데 페이지가 없는 것 → 여러 번 언급된 것은 페이지 생성 후보 (log.md는 과거 기록이므로 제외)
4. **index 누락** — wiki/에 있지만 index.md에 없는 페이지, 또는 그 반대
5. **상충·낡은 주장** — 새 자료로 대체된 정보, 해소되지 않은 상충 callout, `(기준: …)`이 오래된 정보(최신 자료·패치와 비교), 기준 표시가 빠진 수치
6. **미처리 raw** — raw/에 있지만 어떤 `요약-` 페이지의 출처(`raw:`)로도 연결되지 않은 파일 (이미지·PDF 등 첨부는 wiki 본문에서 언급되면 처리된 것으로 본다)
7. **열린 할 일** — 모든 `- [ ]` 항목을 모아 기한 지난 것 강조
8. **연결 제안** — 서로 관련 있어 보이지만 링크가 없는 페이지 쌍, 새로 조사해볼 질문·자료 제안
9. **프로젝트 점검** — `project` 페이지의 `repo` 경로가 실제로 있는지, 오래 갱신되지 않은 `진행중` 프로젝트(회고 넣을 때가 됐는지), 본문에 세부 구현 계획이 복사돼 있지 않은지

## 조건부 규칙 (조건이 되면 적용하고 log에 `schema`로 기록)
| 조건 | 할 일 |
|---|---|
| 한 도메인의 `source` 페이지가 5개 이상 | 도메인 개요 페이지 `개요-<도메인>.md`(type: `topic`) 생성. 전체 목록 금지 — 읽는 순서와 이유, 열린 질문(번호 목록), 다른 도메인과의 연결만 |
| 자료 약 100건 또는 index 항목 약 300개 | 검색 도구(qmd 등) 도입. index는 계속 전체 목차로 유지 |
| 한 도메인이 다른 도메인과 거의 연결되지 않고 별도 공유가 필요 | 볼트 분리 검토. 분리 시 `~/.claude/CLAUDE.md`의 위키 경로도 갱신 |
