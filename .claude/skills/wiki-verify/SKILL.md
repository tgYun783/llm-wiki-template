# 검증 루프 (Ralph 루프)

위키를 수정한 작업은 끝내기 전에 반드시 돌린다. 오류·검토 문제가 0이 될 때까지 1→2를 반복하고(최대 5회), 3으로 기록한다.

1. **기계 검사** — `python3 .claude/wiki_lint.py`를 `ERROR` 0건이 될 때까지 반복한다 (최대 5회).
   - `WARN`은 판단 항목(시점 표시 누락 의심, 미처리 raw, raw 파일명, 빨간 링크, 의존 확인)이다. 고칠 수 있으면 고치고, 아니면 보고에 적는다.
   - `[의존 확인]`은 이번에 바꾼 페이지·시스템 파일에 기대는데 손대지 않은 페이지 목록이다(그래프는 `sources`·본문 인용·시스템 이름 언급에서 자동으로 뽑음). 목록의 페이지를 열어 바뀐 내용이 그 주장에 닿는지 보고, 닿으면 고치고 닿지 않으면 보고에 "확인, 수정 없음"으로 적는다.
   - raw 파일명 위반과 사용자가 직접 고친 내용은 고치지 않고 보고만 한다 (절대 규칙 1·3).
2. **의미 검토** — 글을 쓴 Claude가 아니라 **`wiki-reviewer` 서브에이전트**(새 문맥·읽기 전용)가 검토 항목 8개(리뷰어 파일 `.claude/agents/wiki-reviewer.md`에 있음)를 확인한다. 쓴 사람은 자기 의도를 읽어 버리기 때문이다.
   - 다 쓴 뒤 부른다. 넘길 것: 수정·생성한 wiki 페이지 목록, 관련 raw 파일명, 2회차부터는 이전 회차 문제와 고친 내용.
   - 리뷰어는 고치지 않고 문제만 돌려준다. Claude가 고치고 1로 돌아가, **새 문제 0건인 회차**가 나올 때까지 다시 검토받는다. 지적이 틀렸다고 판단하면 고치지 말고 이유를 보고에 적는다.
   - 고치기 전에 지적마다 원인을 먼저 판정한다: **raw·규칙에 답이 있었는데 틀렸나**(→ 절차 문제: 페이지를 고치고, 같은 지적이 되풀이되면 해당 스킬·보조 파일에 한 줄) / **답이 없었나**(→ 규칙 공백: 페이지를 고치고 규칙 추가를 사용자에게 제안) / **raw·규칙으로도 정답이 갈리나**(→ 사용자에게 묻는다). 대화에서 사용자가 지적·수정해 준 내용을 반영할 때도 같다.
   - 보고(회차마다, 리뷰어 결과 그대로): `의미 검토 N회차 — 1:✅ 2:⚠️2건 수정 3:✅ … 8:✅`
   - 기계 검사 0건은 의미 검토를 대신하지 못한다.
3. **기록** — log.md 항목에 `- 검증:` 줄을 남긴다 (새 log 항목마다 필수, 검사기가 확인).
   - 형식: `- 검증: 기계 검사 N회(오류 0 · 경고 N) · 의미 검토 N회차(마지막 회차 새 문제 0)`
   - 페이지를 바꾸지 않고 log만 추가했으면 `의미 검토 없음(페이지 수정 없음)`.
4. 5회 반복 후에도 오류나 검토 문제가 남으면 멈추고 사용자에게 ① 남은 문제 ② 막힌 원인 ③ 시도한 것 ④ 대안을 보고한다.

## hook이 강제하는 것
- Stop hook은 이 세션이 새로 만든 `ERROR`가 있거나, 바꾼 페이지의 현재 내용에 대해 리뷰어의 "문제 0건" 영수증(SubagentStop hook이 기록)이 없으면 끝내지 못하게 한다 (세션당 최대 5회).
- 페이지를 고치면 영수증이 무효가 되니 마지막 수정 뒤에 다시 검토받는다.
- 세션 시작 전부터 있던 오류(사용자가 Obsidian에서 만든 노트·수정 등)는 막지 않고 알림만 한다. 고치지 말고 보고해 사용자 확인을 받는다 (절대 규칙 3).
