# 자료 넣기 (Ingest)

핵심: raw는 읽기만 한다(사용자가 준 텍스트·URL을 저장할 때만 예외). 쓴 뒤에는 반드시 `wiki-verify`. 페이지 형식은 `.claude/rules/페이지-형식.md`(wiki/ 파일을 다루면 읽힌다).

1. **확인** — 대상 raw 파일을 특정한다. 사용자가 텍스트/URL을 직접 주면 `raw/YYYY-MM-DD_설명.md`로 저장해도 되는지 묻고 저장한다 (이때만 raw에 쓸 수 있다; 원문 그대로 저장, 편집 금지. 설명은 짧은 케밥케이스). 파일명이 규칙과 다르면 알려준다.
2. **읽기** — 전문을 읽는다. 이미지가 있으면 필요한 것만 따로 본다.
3. **핵심 공유** — 채팅으로 3~5줄 핵심 요약과 "위키에 반영할 계획"(생성/수정할 페이지 목록, 붙일 도메인 태그, 새 도메인이 필요하면 그 제안)을 먼저 보여준다. 사용자가 강조점을 지시하면 따른다. (사용자가 "알아서 해", "일괄 처리"라고 하면 이 단계를 생략한다.)
4. **요약 페이지 작성** — `wiki/요약-<slug>.md` (type: source). 자료 유형별 섹션은 `references/자료유형.md`.
5. **전파** — 관련 `concept` / `entity` / `topic` / `project` / `idea` 페이지를 생성하거나 업데이트한다. 새 정보가 기존 내용과 다르면 상충 callout으로 표시한다. 한 자료가 5~15개 페이지를 건드리는 것이 정상이다.
6. **교차참조** — 새로 만든 페이지에서 나가는 링크뿐 아니라, 기존 페이지에서 새 페이지로 **들어오는 링크**도 추가한다.
7. **index.md 업데이트** — 새 페이지를 해당 카테고리에 추가, 기존 항목의 한 줄 설명이 바뀌었으면 수정.
8. **log.md 기록** — 맨 아래에 추가.
9. **검증 루프** — `wiki-verify` 스킬로 오류 0이 될 때까지 반복한다.
10. **보고** — 생성/수정한 페이지 목록, 핵심 한 줄, 검증 결과를 채팅으로 짧게 보고. 검증 결과에는 기계 검사 반복 횟수·남은 경고와 함께 **의미 검토 회차별 결과**(`wiki-verify` 2번)를 반드시 적는다.

## 보조 파일 (해당할 때만 읽는다)
- `references/자료유형.md` — 4단계 유형별 요약 틀
- `references/일괄.md` — 여러 건을 한 세션·묶음으로 넣을 때 (순서표, 작성 → 검토 → 수정 사이클, 되풀이된 리뷰 지적)
