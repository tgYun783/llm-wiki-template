# 여러 건 일괄 넣기

자료가 여러 건이면(예: 공식 문서 묶음) 1건 절차를 그대로 반복하되 아래를 더한다.

## 순서표
- 시작 전에 대상 raw 전체를 주제별로 묶어 순서를 정하고, 개요·허브가 될 문서를 앞에 둔다.
- 순서표는 세션 안의 작업 도구다. 다음 세션으로 넘길 때는 log 항목에 남은 순서를 raw 파일명으로 적는다(번호는 세션마다 다시 짤 수 있으니 번호에 기대지 않는다).
- 사용자가 "알아서 해", "일괄 처리"라고 하면 넣기 3단계(핵심 공유)는 생략한다. 새 도메인이 필요하면 만들고 보고에 적는다.

## 작성 → 검토 → 수정 사이클 (1건씩)
1. 작성 에이전트가 1건을 쓴다(요약 + 전파 + index + log).
2. `wiki-reviewer`가 검토한다.
3. 지적은 **같은 작성 에이전트**(SendMessage)에게 돌려 고치게 한다.
4. **같은 리뷰어**에게 재검토받아 새 문제 0건이면 다음 건으로.
- log는 1건마다 `(묶음 이름 N/전체)`를 제목에 붙여 남긴다.

## 되풀이된 리뷰 지적 (쓰기 전에 확인)
1. 넘김 문서를 순서표 번호로 가리키지 않는다 — 독자가 풀 수 없다. 문서 제목·링크로 쓴다.
2. 하위 종류의 성질을 묶음 전체에 붙이지 않는다.
3. 상충은 두 출처의 **직접 진술끼리만** 단다. 한쪽이 말하지 않은 것은 상충이 아니다(필요하면 해석).
4. 새 상충을 달면 기존 집계 줄(상충 N건 등)과 index 설명도 함께 갱신한다.
5. 개수(표 행, 항목 수)는 raw에서 직접 센다.
6. 원문 권고 강도(must·should·recommend·can)를 바꾸지 않는다.
